With no surrogate underneath it the model beats a uniform draw (+0.0205, p = 0.008), so it is not picking at random — but the effect is 3.7× smaller than BO’s. Once the GP is underneath it, the model adds nothing measurable (+0.0141, p = 0.154) — whatever it knows, the surrogate already knew.

The baseline decides the headline. Against bo_ei, bo_llm_select is a win: +0.0106, p = 0.0153. Against its own control bo_random_select — the same GP shortlist, the same size, a uniform pick instead of the model’s — the same arm gives +0.0141, p = 0.1536, ns. Same arm, same data; one baseline says the model helps and the other says it does not. The second is the honest one, because it is the only one that holds the shortlist fixed.

Wilcoxon signed-rank on per-seed AUC. “Buys nothing measurable” is not the same as “is equal”: with 20 seeds this design detects roughly a 0.02 AUC difference, so a real effect smaller than that would not show up here.

The gate: is the agentic action space winnable at all?

Run before spending a single model call. Every fixed acquisition alone, against a hindsight ceiling that switches each round to whichever acquisition reaches the best true value.

Headroom is the ceiling minus the best fixed acquisition, not minus ei. If ucb alone beats ei alone, that is a better fixed policy, not evidence for adaptivity — and crediting it to an agent would repeat the mistake the warm-start control was built to catch.

Serving the model

Every model number below is Qwen3.5-4B, Q8_0 GGUF (unsloth), served locally by llama.cpp — the same model and quantisation as the project’s earlier arms, so these results are directly comparable to them and no model-scale confound is introduced.

llama serve -hf unsloth/Qwen3.5-4B-GGUF:Q8_0 --port 8080     --ctx-size 16384 --n-gpu-layers all --reasoning-budget 0

Greedy decoding (temperature 0, top_k 1, fixed seed) and llama.cpp compiles the JSON schema to a GBNF grammar, so a schema-valid response is guaranteed by construction. Every response is cached under a hash of the exact request including the backend’s sampling settings, so a rerun makes zero model calls.

A model that was tried and not used

IBM Granite 4.2 8B (Q4_K_M) was served first, as the larger-model control. It works, but it needs the opposite reasoning flags to Qwen, and the recipe this repo documents for Qwen actively breaks it. Recorded because the failure is silent in one case and cryptic in the other:

server flagsresult on granite
none empty content, finish_reason=length — the model spent its whole budget thinking and never emitted the JSON
--reasoning off --reasoning-budget 0
(the documented Qwen recipe)		 HTTP 500, Unexpected empty grammar stack on every schema — budget 0 forces a think block open, the reply begins with </think>, and the JSON grammar applies from token 0, so that tag can never be produced
--reasoning off --reasoning-format deepseek works — the thought goes to message.reasoning_content and message.content is bare JSON

Granite was dropped in favour of Qwen because Qwen is the model every other arm in this project was run on, so keeping it removes a model-scale confound rather than introducing one. Throughput was not the reason: measured end to end through the campaign loop the two are comparable — Qwen3.5-4B Q8_0 sustains about 38 schema-constrained calls per minute against granite 8B Q4_K_M’s ~40. That rate is what caps the model arms at a 9-task PMO subset: a per-round selector is 99 calls per seed per task, so two such arms across all 22 tasks would be roughly 10 hours of decode.
