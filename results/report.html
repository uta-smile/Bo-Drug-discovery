Three ways to pair an LLM with molecular Bayesian optimisation

A local Qwen3.5-4B narrows the library, or picks which candidate gets assayed, or chooses what to test first. Each is measured against plain BO, random search, a matched non-LLM control, a ceiling that already knows every answer, and published baselines from the PMO benchmark.

Verdict

None of the three pairings beats plain BO. Across three quite different couplings — narrowing the library, choosing which candidate is assayed, and choosing what to test first — no LLM arm is significantly ahead of the GP on its own, and the constraint arm is significantly behind at a 100-call budget.

The one arm that gains ground, the warm start, is matched by a free MaxMin diversity heuristic choosing from the same 40 molecules with no model involved — and the heuristic is in fact slightly ahead at both budgets. The model says as much itself: its recorded rationales are explicitly diversity arguments (“Core Scaffold Diversity… distinct structural scaffolds… maximize information gain”). It is doing MaxMin selection in prose.

-0.030 Constraint at 100 calls (p = 0.006). Significantly worse. A bad mask is absorbing — it excluded the best compound in 19 of 20 proposals and BO never recovers.
-0.018 Selection at 50 calls (ns). With list-position bias removed it agrees with BO 3× more than chance — a noisy copy of the acquisition function, not an improvement on it.
+0.017 Warm start at 50 calls (p = 0.23, ns). Gains ground, but its own free control gains +0.022 — more, not less.

Headroom is not the problem: the ceiling arm, which simply knows the answers, is worth +0.080 at 50 calls (p < 0.001). A good constraint wins comfortably here — this model just does not find one.

Correction: an earlier version of this page reported the warm start as a significant win (+0.030, p = 0.024). That was measured with stereochemistry-blind fingerprints. After fixing the representation (see Search space) the effect is no longer significant and the non-LLM control overtakes it. Every number here was regenerated after the fix.

Scope: Qwen3.5-4B running locally. It misidentifies the series' chemotype in every prompt format tried — calling anilinoquinazolines a “pyrazolo[3,4-d]pyrimidine core” — so these are results about a small local model, not about language models in general. The harness is backend-agnostic.

# 4. The main sweep: all arms, 20 paired seeds
python scripts/run_lookup_experiment.py \
    --dataset data/chembl/egfr_anilinoquinazoline.csv \

    --llm-arm --select-arm --warmstart-arm --shortlist-k 15 \
    --out results/bench_final_b50

# 5. The public benchmark, against PMO's published baselines
python scripts/run_pmo_experiment.py --seeds 5 --budget 1000 \
    --tasks albuterol_similarity celecoxib_rediscovery deco_hop \

# 6. Regenerate this page from whatever is in results/
python scripts/build_report.py

Determinism: the model runs greedy (temperature 0, top_k 1, fixed seed) and every response is cached by a hash of the exact request, so a rerun makes zero model calls and reproduces the tables byte for byte. Delete data/cache/llm* to force fresh generations.

Search space

Bounds and dimensionality

This is not continuous box-bounded BO. There are no lower/upper bounds on continuous variables and no design matrix to optimise over. The search space is a discrete, fully enumerated set of molecules, and the acquisition function is maximised by scanning it rather than by any gradient or inner optimiser. “Bounds” here means membership rules, not intervals.

Search spacediscrete, 2,086 enumerated molecules (PMO tier: 249,455)
Decision variableone categorical index over the library — effectively 1-D, with 2,086 levels
Membership boundsanilinoquinazoline core substructure; 17–55 heavy atoms (median 33); measured pIC50 in [4.00, 11.00]
Additional bound (constraint arms)a boolean mask over the library; degrades to a soft penalty below 20 unseen survivors
Acquisition optimiserexhaustive scan of all unevaluated members — no local optimiser, no restarts, global by construction

Where dimensionality does enter: the kernel's feature space

The GP does not see molecules, it sees fingerprints — and that is the only place a dimension count is meaningful.

2,048nominal ECFP4 bits. Of these 1,830 are ever set in this library and 1,827 actually vary — the rest carry no signal at all.
3.0%density: a molecule sets 62 bits on average (range 26–94). The representation is extremely sparse.
10.1 effective rank of the Tanimoto Gram (participation ratio). Despite 2,048 nominal dimensions the kernel is dominated by ~10 directions; 480 eigenvalues are needed for 90% of the spectrum.

That gap — 2,048 nominal, ~10 effective — is precisely why a Tanimoto kernel is used instead of a squared-exponential one. An RBF GP would need a lengthscale per dimension over 2,048 sparse binary features, which in practice collapses to either “everything is identical” or “nothing is related”. Tanimoto has no lengthscale to fit, so the curse of dimensionality never arises: pairwise similarity is the whole model. Observed similarity is mean 0.30, median 0.28, 95th percentile 0.47 — a genuinely congeneric series, tight enough for the surrogate to generalise but not degenerate.

Molecules the surrogate could not tell apart — found, and fixed

Maximum off-diagonal Tanimoto in this library was 1.0, meaning some distinct library entries were identical to the GP. RDKit's Morgan generator ignores stereochemistry by default, so E/Z and R/S isomers collapsed onto the same fingerprint while their measured activities did not. The worst pair differed by 3.00 log units — a thousand-fold in potency, invisible to the model:

CN(/N=N/c1ccc2ncnc(Nc3cccc(Cl)c3)c2c1)C(=O)OCCl   pIC50 6.41
CN(/N=N\c1ccc2ncnc(Nc3cccc(Cl)c3)c2c1)C(=O)OCCl   pIC50 9.41

A GP handed two identical inputs with different targets can only average them, which puts an irreducible noise floor under every prediction and shows up as a large fitted eta. Enabling includeChirality removes 51% of the collisions:

ECFP4 settingIdentical pairs Molecules involvedLargest pIC50 gapPairs differing > 0.5 log
includeChirality=False — RDKit default 133204 of 2,086 3.0042
includeChirality=True — in use (v2-chiral) 6594 of 2,086 2.0315

The remaining 65 pairs are regioisomers that ECFP4 at radius 2 genuinely cannot separate; those need a larger radius or a different descriptor, not a flag. Density and effective rank are unchanged — chirality alters which bits are set, not how many — so this is a targeted correction rather than a different representation.

Every result on this page was regenerated after the fix. The fingerprint recipe is versioned (v2-chiral) and that version is part of the pooled-fingerprint cache filename, so a representation change can never be silently mixed with stale data.

What BO actually does

What is optimised, what is updated, what gets suggested

The objective. Maximise measured pIC50. The campaign never sees the library's unobserved values — only the molecules it has paid for.

What is fitted, every round. Not the molecules: the GP's own hyperparameters. After each new measurement the surrogate is refitted from scratch by exact log marginal likelihood — the noise-to-signal ratio eta is scanned over a fixed 9-point grid, and for each one the signal variance has a closed form, so there is no gradient step and no optimiser seed. The posterior mean and variance over all unevaluated molecules are then recomputed.

Two controls carry the argument. A random mask of the same tightness significantly hurts (−0.081 at 100 calls), which kills the obvious objection that any restriction helps a small-budget search. And the purely statistical mask is neutral (−0.003, p = 0.65), so a win could not have been dismissed as the model merely summarising descriptors.

The three pairings

1 — Constraint: the model narrows the library

The model sees the SAR so far plus a menu of 28 substructures mined from the library, and returns a mask. It chooses by index and never writes SMARTS: asked to write them, this model produced an invalid pattern every single time, the arm collapsed to a molecular-weight range keeping 89% of the library, and the experiment measured typing rather than chemistry.

1 / 20proposals retain the single best compound. A mask is absorbing — once the optimum is fenced off, BO cannot recover for the rest of the run.
23.5% → 31.0%library kept vs true top-1% captured. A perfectly uninformative mask would capture 23.5%.
0.7350AUC when the constraint is re-proposed 6× per run instead of once (0.7340). More evidence does not help — the “it only sees 10 examples” hypothesis is dead.

2 — Selection: BO shortlists, the model picks

Each round BO ranks candidates, the top 15 go to the model, and it chooses which one costs an oracle call. A bad pick costs one evaluation, so unlike a constraint it is recoverable. It costs one model call per evaluation — about 40× the constraint arm. shortlist_k is the dial: k=1 is exactly plain BO (pinned by a test, including on a flat acquisition surface), k = all candidates is pure selection.

The confound this arm exposed

Presented in acquisition order, “picks position 0” and “agrees with BO's top candidate” are the same event. The first run's choice distribution was strongly non-uniform but the shape was positional — peaks at the first and last entries, a trough at the second. Textbook primacy/recency bias impersonating judgment. Shuffling the shortlist into a seeded random order and mapping the answer back decouples them; these are the resulting acquisition ranks over 800 decisions:

acq. rank01234567891011121314
picks1718057445643413546303551354234

It picks BO's own top candidate 21.4% of the time against 6.7% for chance, and its mean chosen rank is 5.31 against 7.0 for uniform. So with position bias removed it does carry real signal about what the GP likes — and it still does not help, because agreeing with BO a fifth of the time and deviating the rest is worse than simply taking BO's pick. It is a noisy approximation of the acquisition function, not an improvement on it.

3 — Warm start: the model picks what to test first

With nothing yet measured, the model chooses the first 10 compounds from a seeded 40-molecule sample. This is the best case a language model gets: there is no data, so the surrogate has nothing to offer and prior knowledge is all there is. One call per run.

The comparison is unusually tight — the sample is drawn with the campaign's own seed, the same draw plain BO's random design comes from, so the only difference is which members of an identical pool get bought first.

Public benchmark

PMO — comparing against 25 published algorithms

Every other number here comes from an oracle we built, which is exactly what a reviewer distrusts. PMO (“Sample Efficiency Matters: A Benchmark for Practical Molecular Optimization”, Gao, Fu, Sun & Coley, NeurIPS 2022) fixed 23 tasks, capped the oracle budget, and re-ran 25 algorithms — finding that most “state-of-the-art” methods stop beating their predecessors once the budget is controlled. Tasks are distributed through PyTDC; a task is a scoring function from SMILES to [0, 1].

Our search space is the ZINC-250k pool (249,455 molecules), so the like-for-like published baselines are the library-based ones: screening (random sampling from the pool) and MolPAL (BO over the pool). The generative baselines search unrestricted chemical space and will score higher partly for that reason alone.

Ground truth

How far from the actual answer?

A PMO task is a scoring function that costs microseconds, so the best answer on this library is not something to be estimated — it can be looked up. scripts/pmo_ground_truth.py scores all 249,455 ZINC-250k molecules with the same TDC oracle the campaigns use, sorts them, and records the top of the distribution. The mean of the ten best scores is the ceiling on the AUC top-10 metric: the metric averages the top-10 curve, the curve cannot exceed that value, so neither can any method on this pool.

This is the optimum of the library, not of the task. These functions are defined over all of chemical space, and the rediscovery targets are not in ZINC-250k — celecoxib_rediscovery scores 1.0 for celecoxib itself, but the best molecule the pool contains scores 0.4583. Generative methods that build molecules are not bounded by these numbers. Library methods, including every arm here and PMO's own screening and MolPAL, are.

The surrogate closes almost all of the gap; what is left is too small for the selector to be measured in. Across 9 tasks, random sampling finds 74% of the best top-10 in the pool at 1,000 calls and plain BO finds 95.2%, so the GP closes about 21 of the 26 available points. Letting the model choose from BO's shortlist moves that to 95.1%. It is ahead of plain BO on 7 of 9 tasks — consistent in sign, but by a median of +0.0013 AUC, with a sign test over tasks at p = 0.18. On 9 of 9 tasks the paired difference is smaller than its own standard error. The honest reading is an effect too small to resolve at this seed count, not an effect shown to be absent.

The one task with real room left is isomers_c7h8n2o2, where BO reaches 90% of the ceiling and random manages 30% — and it is also where the selector's largest margin sits. At the other end, qed is saturated: random sampling alone finds 99% of the best top-10 in the pool, so nothing measured on that task separates any two methods. Neither fact is visible from a ranking of arms against each other.

Corrections

Bugs found while building this

Listed because each one produced a plausible-looking number before it was caught, and every one was found by a test asserting an invariant rather than by reading the output.

A constraint arm that silently wasn't one

The PMO runner built its LibraryContext directly, leaving mols empty, so every substructure mask came back all-False — indistinguishable from "matched nothing". The arm degraded to unconstrained and reported ΔAUC = +0.0000 on every task, p = 1.0. A clean zero reads like a finding. Molecules and descriptors are now computed lazily, so a context is correct however it is built, and the runner prints constraint modes.

Molecules the surrogate could not tell apart

RDKit's Morgan generator ignores stereochemistry by default, so 133 pairs — ~10% of the library — were identical to the GP while their activities differed by up to 3.0 log units. includeChirality=True halves it. This one changed a conclusion: the warm start was significant before the fix and is not after.

False coverage figures shown to the model

Menu entries were counted by how often a scaffold occurred, not how often its query matches. The anilinoquinazoline core was advertised at 25.3% of the library; it actually matches 100%, because the library was selected by that core. Candidates are now counted with the same query used at match time.

Generic scaffolds that could never match

MakeScaffoldGeneric maps benzene to C1CCCCC1, which as a query matches aliphatic rings and so matches none of the aromatic molecules it came from — advertised at 50% coverage, actual coverage zero.

Answers lost to truncation

The selection schema emitted reasoning before choice, so a response overrunning max_tokens lost its answer — 6 of 41 calls in a pilot. In aggregate a 17% failure rate looks exactly like a model that agrees with BO. choice now comes first.

Position bias impersonating judgment

The shortlist was shown in acquisition order, so "picks position 0" and "agrees with BO's top candidate" were the same event. The choice distribution was peaked at both list ends. Shuffling and mapping back decoupled them — and only then was the model's real (modest) agreement with the acquisition function measurable.

Inconsistent tie-breaking

Plain BO broke ties at random; the selector shortlist broke them at index 0. On a flat acquisition surface — every EI numerically zero, the normal early state — the claim "k=1 is plain BO" quietly failed. Both now share one ranking function.

A mask recomputed every round

Constraints were re-evaluated each iteration even when unchanged: ~10 s per round on a 60k pool, over an hour wasted per PMO campaign. Masks are now cached on the library context, keyed by the constraint's spec hash so a genuinely new proposal still recomputes.

Everything in results/
